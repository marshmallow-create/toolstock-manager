# ToolStock Manager 現行仕様書

現行実装の仕様です。今後の機能追加では、本書と関連する設計・テストを更新します。

## 1. 目的と対象

1工場の切削工具について、工具情報、実在庫、入庫・出庫、変更・取引履歴を管理します。社員IDとパスワードで利用者を識別します。現在の実行環境はローカルのNext.jsアプリとPostgreSQLです。

外部送信、本番公開、実発注は今回の完成範囲に含みません。

## 2. ロールと権限

| 操作 | 作業者 WORKER | 管理者 ADMIN |
| --- | --- | --- |
| 工具・在庫の参照 | 可 | 可 |
| 工具登録 | 可 | 可 |
| 工具情報変更（在庫・発注ライン・発注数を含む） | 不可 | 可 |
| Excel一括登録・変更・確認・テンプレート取得 | 不可 | 可 |
| 入庫・出庫 | 可 | 可 |
| 工具変更履歴の参照 | 可 | 可 |
| 入出庫履歴 | 全件。新規登録前の履歴を含む | 全件 |
| 発注リストの参照 | 可 | 可 |
| 単価の参照・範囲検索 | 可 | 可 |
| 工具登録時の単価入力 | 可 | 可 |
| 既存工具の単価変更 | 不可 | 可 |
| 入出庫の取消 | 不可 | 可 |
| ユーザー登録・変更 | 不可 | 可 |

サーバー側で毎回認証・認可します。画面にボタンを隠すだけではなく、APIにも適用します。単価の読み取り制限と、工具登録・変更の権限は別です。

## 3. ログインと共通表示

- `/` は `/login` へ転送し、ログイン成功後は `/dashboard` へ移動します。
- ログインは画面中央の最大448pxのカード内に、社員ID・パスワード・ログインボタンを縦に配置します。
- セッションは無操作30分、ログインから最大8時間で終了します。
- 社員ID単位で15分間に5回までログインを試行でき、6回目以降を制限します。
- 業務画面の最大幅は1600px。ツール名、画面見出し、本人の氏名・社員ID・ロール、ログアウトを表示します。
- メニューはマイページにだけ表示します。その他の認証済み画面には「マイページへ戻る」を表示します。
- 主要操作、補助操作、リンク、展開欄には共通の色・フォーカス表示を使います。背景は薄いグレー、カードは白、主操作は緑系、リンク・補助操作は青系です。
- 表は狭い画面で表の内側を横スクロールします。フォームは画面幅に応じて折り返します。
- エラーは画面に表示します。ユーザー管理では「保存しました。」の成功メッセージと、画面下の権限変更に関する注意文を表示しません。

## 6. 工具登録・変更

### 入力項目

| 項目 | 登録 | 変更 | 制限 |
| --- | --- | --- | --- |
| 品目コード | 必須 | 読み取り専用 | 半角英数字・ハイフン・アンダースコア32文字以内。大文字化して一意 |
| 品目名 | 必須 | 必須 | 100文字以内 |
| カテゴリー | 必須選択 | 必須選択 | 下記5種類 |
| 在庫 | 初期値0 | 現在の工具全体の実在庫 | 0～2,147,483,647の整数 |
| 発注済み | 自動集計値0を表示 | 編集欄なし | 発注明細から自動集計 |
| 発注ライン | 初期値0 | 変更可 | 0～2,147,483,647の整数 |
| 発注数 | 初期値0 | 変更可 | 0～2,147,483,647の整数 |
| 単価 | 必須、初期値0 | 管理者が変更可 | 0以上、整数部12桁・小数部2桁以内 |
| 部門 | 任意選択 | 任意選択 | 下記4コード。未設定可 |
| 棚番 | 任意 | 任意 | 通常100文字以内。既存の長い棚番は保持可能 |
| 状態 | 有効で登録 | 有効・無効を選択 | 工具の物理削除は提供しない |

単価の表示は1円単位ですが、保存値は引き続き `Decimal(14,2)` です。小数部2桁以内の入力を受け付け、その値を保持します。入力値や既存データを表示に合わせて整数へ変更しません。工具一覧・詳細・履歴・Excel確認表の金額は同じ表示規則を使います。

### カテゴリー・部門

| 表示名 | 保存コード |
| --- | --- |
| ドリル | DRILL |
| エンドミル | END_MILL |
| タップ | TAP |
| リーマ | REAMER |
| チップ | INSERT |

部門は `17314`、`17361`、`17362`、`17363` のみです。候補外の値はサーバーでも拒否します。カテゴリーは既存英語コードと日本語名を読み取り・検索時に対応付けます。登録・更新時は保存コードへ正規化します。

### 保存時の処理

- 工具登録時に工具、在庫方針、内部の在庫参照先、初期在庫、必要な発注候補、監査を同じトランザクションで保存します。
- 正数の初期在庫は入庫履歴も作成します。0では数量0の履歴を作成しません。
- 在庫変更は差分をADJUSTMENTとして記録し、変更前後の残高と操作者を残します。引当数を下回る変更は拒否します。
- 編集画面の表示後に在庫が変わった場合、古い値による上書きを拒否します。
- 発注数の変更では現在のOPEN候補をDISMISSEDにし、正数なら新しいOPEN候補を作成します。同数の保存では作り直しません。
- 発注ラインのみを設定する保存では、内部の安全在庫を0、目標在庫を発注ラインと同値にします。
- 数量単位は画面に編集欄を出さず、既存値を保持します。新規登録の数量単位は内部既定値「個」です。メーカー・型番は2026年11月10日にDBから除去し、削除前の値は監査記録へ退避しました。
- 在庫や取引履歴のある工具は数量単位を変更できません。品目コードも変更できません。
- 「工具全体の在庫方針」の旧入力欄と、旧画面の注意文は表示しません。

### Excel一括登録・変更

管理者のみ、工具登録画面の「Excelで一括登録・変更する」から `/tools/import` を利用します。同じ画面で新規登録と既存工具の変更を切り替えます。画面、テンプレート取得、確認・確定APIと保存トランザクションを `tools:import` 権限で制限します。作業者にはリンクを表示せず、直接アクセスも拒否します。1件ずつの通常登録とは権限を分けます。

1. 新規登録・既存工具変更を選び、そのモードのExcelテンプレートをダウンロード。
2. 品目コード・品目名・カテゴリー・在庫・発注ライン・発注数・単価・部門・棚番を入力。
3. .xlsxをアップロードし、全行の内容・行番号・入力エラーを確認。変更モードは変更前→変更後を表示。
4. エラーがない場合だけ一括登録・一括変更を確定し、マイページへ戻る。

両モードとも同じ9列で、1回200件、ファイル2MiB以下です。新規登録は「工具登録」シートを使い、品目コード・品目名・カテゴリー・単価は必須、数量の空欄は0、部門・棚番は未設定可です。既存コードを拒否します。変更は「工具変更」シートを使い、既存工具に一致する品目コードが必須です。他の項目の空欄は変更なし、0の入力は0への変更です。部門・棚番も空欄で消去できません。未登録コードを拒否します。分類・部門等の制限は通常保存と共通で、ファイル内重複・列違い・数式・セル結合も拒否します。別モードのシートは使用できません。

テンプレートの単価列は `numFmt: '0'` で小数を表示しません。小数部2桁以内の単価は入力でき、取り込み時にも小数値を保持します。

確認時はDBへ保存しません。確定時にもファイル・権限・重複を再確認し、全件を1トランザクションで保存します。新規登録は工具・初期在庫・取引・候補・監査を作成し、変更は通常の工具変更と同じ在庫修正・候補更新・監査・変更履歴の処理を使います。エラー時は全件を戻します。変更の確定には確認で返された `previewToken` が必要です。工具・全在庫・在庫方針・OPEN候補とファイルの指紋を照合し、確認後の変更は409で拒否します。最新内容で再確認してから確定してください。ファイルをサーバーのファイル領域やDBへ保管しません。

## 7. 工具詳細の表示順

1. 工具情報：一覧と共通の表。「工具情報変更」から編集画面へ移動。
2. 工具変更履歴：新しい順に最大3件。
3. 入庫・出庫：常時表示し、sm幅以上では横並び、小さい画面では縦並び。
4. 直近の入出庫履歴：閲覧権限内の最新5件。

ページ最下部の「入出庫履歴へ」から、工具で絞り込まない `/history` を開けます。「マイページへ戻る」と同じ文字サイズ・下線付きリンクで表示します。作業者・管理者ともに利用でき、履歴の閲覧範囲は既存の権限に従います。保管場所別在庫の旧表と「履歴を検索する」の旧リンクは表示しません。

### 工具変更履歴

列は「変更日時・変更内容・操作者」。日時は日本時間で秒まで表示し、操作者は氏名と社員IDを表示します。

既存の監査記録から、工具情報、在庫、発注数の変更を読み取ります。変更内容は「棚番：A-01 → B-02」のように表し、同じ値の保存は表示対象にしません。単価を閲覧できない利用者には金額を出さず「単価を変更」と表示します。履歴がなければ「工具の変更履歴はありません。」と表示します。

表示項目は工具編集に合わせ、品目名・カテゴリー・在庫・発注ライン・発注数・単価・部門・棚番・状態とします。内部で自動補正する安全在庫・目標在庫や、編集項目にない旧メーカー・型番・数量単位は工具変更履歴へ表示しません。金額の小数桁など表記だけの差も除外します。過去の監査にも同じ表示ルールを適用し、内部項目だけのイベントは最大3件の枠に含めません。詳細な監査記録は保持します。

最大3件は監査イベント単位です。1回の保存で工具情報・在庫・発注数を変えると複数行になることがあります。操作者名は現在のユーザー情報から表示します。削除した過去の記録や、監査のない変更を推測して補いません。

## 8. 入庫・出庫

- 保管場所の選択欄はありません。内部在庫参照先、棚番に一致する在庫、または唯一の有効な在庫を自動で使います。対象を特定できない場合は操作させず案内を表示します。
- 数量は初期値1、正の整数。直接入力と「−」「＋」で変更できます。
- 入庫後・出庫後の見込みを即時表示します。実行時はサーバーで最新在庫を再確認します。
- 通常取引に理由・設備の入力欄はありません。
- 出庫は実在庫から引当を引いた数量を超えられません。入庫後の在庫も整数上限を超えられません。
- 無効な工具・参照先への新規取引は拒否します。
- 在庫・取引履歴・監査を原子的に保存します。二重送信では同一キーと入力を照合し、同じ確定結果を返します。
- 入庫・出庫の成功時は、最新の在庫を反映した対象工具の詳細 `/tools/[id]` へ戻ります。履歴一覧からの取消ではページ遷移せず、現在の検索条件・ページ番号・スクロール位置を維持して一覧を更新します。JavaScriptが使えない場合も、送信した履歴一覧の条件とページ番号へ戻ります。

## 9. 入出庫履歴

### 検索

画面の順序は、品目コード、カテゴリー、入出庫履歴、操作者、開始日、終了日、単価下限・上限、検索・条件クリアです。

品目コードは部分一致、カテゴリーは選択式です。入出庫は数量の増減方向で絞ります。全ユーザーが、ユーザー登録前を含む全員の過去履歴を参照できます。操作者の候補は全ユーザーで、選択した操作者の取引へ絞り込めます。単価の閲覧・範囲検索は全ユーザーに許可し、取消は管理者だけに許可します。

日付は日本時間の開始日00:00以上・終了日の翌日00:00未満。単価の上下限は両端を含み、片方のみ指定可能です。単価の閲覧・範囲検索には共通の `prices:read` 権限を使い、両ロールに許可します。

### 一覧・取消

- 新しい日時、同時刻はIDの降順で1ページ50件。検索条件をページ切り替え時も保持します。
- 列は左から「日時・品目コード・品目名・カテゴリー・入出庫履歴・数量・操作者・在庫数・単価」。
- 入出庫欄は符号で入庫・出庫を表示し、数量は当該取引の絶対値です。
- 在庫数はその在庫参照先における取引直後の実在庫。単価も取引時点の記録を使います。未知の値は「—」。
- 単価変更は過去の取引単価を書き換えません。取消は元の単価を引き継ぎます。
- 管理者だけが一覧内の「取消」を開き、理由入力なしで全量を逆取引で取り消せます。取消中の二重操作を抑止し、完了後は「取消済み」と表示します。監査・DBの理由にはシステムが「入出庫履歴から取消」を補います。既存APIで明示した理由と成功済み再送は引き続き扱います。
- 元の取引は変更・削除しません。二重取消、取消の再取消、在庫・引当制約を破る取消は拒否します。

## 10. ユーザー管理

管理者のみ利用できます。登録項目は社員ID、氏名、ロール、初期パスワードです。社員IDは半角英大文字・数字・ハイフン・アンダースコア32文字以内、氏名80文字以内、設定するパスワードは8～128文字です。

一覧は社員IDの部分一致検索、1ページ20件。行の「編集」を開いて氏名、ロール、状態、新しいパスワードを変更します。空の新パスワードは変更なしです。操作ボタンは共通スタイルを使います。

ロール・状態・パスワードを変更すると対象セッションを失効します。自分自身の無効化・降格と、有効な管理者がいなくなる変更は禁止します。過去の業務履歴は保持します。

削除済みユーザーは一覧・検索・変更の対象外とし、ログインとセッション利用を拒否します。物理削除せず `deleted_at` で記録し、過去の履歴の操作者との関連を保持します。画面にユーザー削除操作は提供しません。

通常の書き込みはJSONまたはHTMLフォームを受け、Originを照合します。JSONは結果とHTTPステータス、HTMLフォームは303転送で応答します。通常入力サイズ上限は8KiB。一括登録・変更は専用multipart受付を使い、ファイル2MiB・multipart全体は2MiB+64KiB・展開後8MiBまでに制限します。テンプレート取得・取り込みのmode省略時は既存互換のcreateです。主なエラーは400（入力）、401（未認証）、403（権限・Origin）、404（未存在）、409（競合）、413（サイズ）、429（ログイン試行制限）、503（接続等）です。

## 12. 今後の機能追加との境界

発注リストは実装済みですが、実際の発注確定・発注先への送信は行いません。

現在、発注候補数の保存・発注残の読み取り集計はありますが、発注承認、発注書、注文確定、部分入荷、発注明細連携、返品の操作画面・ワークフローは未実装です。

独立した棚卸・保管場所・設備・仕入先・購買条件の旧管理画面・旧APIは提供しません。管理者向け「データ管理」の表形式編集画面・専用API・専用権限も2026年11月10日に廃止しました。`/admin/data` と `/api/admin/data/[table]` は404です。この機能の廃止に伴うDBの削除は行いません。

設備・購買条件のDBモデルと工具のメーカー・型番、取引の設備IDは別のDB整理で2026年11月10日に監査退避後に削除しました。仕入先・発注・発注明細は発注残集計の参照元として保持します。工具変更による在庫修正は独立棚卸画面とは別に実装されています。

DBバックアップ・復元の定期実行、本番環境の構築・運用、通知、外部連携は現在の実装範囲外です。本番運用先・規模、社内ID連携、発注先と送付・承認方法、複数工場、返品・再研磨・貸出の扱いは今後の要件で決定します。今後追加する機能は本書・権限表・DB移行・テストを併せて更新してください。

## 13. 発注リスト

マイページのメニューで「入出庫履歴」の直下に「発注リスト」を表示します。全ログインユーザーが単価の金額も含めて参照できます。

表示列は左から「日時・品目コード・品目名・カテゴリー・発注数・操作者・単価・部門・発注」。品目コードと品目名は工具詳細へのリンクです。単価は小数なし、日時は日本時間。発注列は空欄とし、確定操作や「済」の表示は今後追加します。

出庫後の工具全体の実在庫が、発注ライン＋発注済み（注文確定済み・一部入荷の未入荷数）の合計より厳密に小さいとき、出庫と同じトランザクションで掲載します。等しい場合は掲載しません。失敗した出庫や成功済み要求の再送では掲載を増やしません。

工具ごとに1行とし、日時・操作者は条件を満たした最新の出庫を参照します。発注数は現在の工具情報の発注数です。行は最新日時順・1ページ50件。導入前の出庫は遡って掲載しません。入庫・取消・工具編集では行を新規作成・削除せず、一度掲載された行は今後の発注処理を追加するまで保持します。
