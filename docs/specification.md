# ToolStock Manager 現行仕様書

基準日：2026年11月8日。2026年11月9日にExcel一括登録を追加。利用者との画面調整を反映した実装時点の仕様です。今後の機能追加ではこの文書を更新します。以前のPhase計画・元の開発指示と相違がある場合は、本書を現在の基準とします。

## 1. 目的と対象

1工場の切削工具について、工具情報、実在庫、入庫・出庫、変更・取引履歴を管理します。社員IDとパスワードで利用者を識別します。現在の実行環境はローカルのNext.jsアプリとPostgreSQLです。

外部送信、本番公開、実発注は今回の完成範囲に含みません。

## 2. ロールと権限

| 操作 | 作業者 WORKER | 管理者 ADMIN |
| --- | --- | --- |
| 工具・在庫の参照 | 可 | 可 |
| 工具登録 | 可 | 可 |
| 工具情報変更（在庫・発注ライン・発注数を含む） | 可 | 可 |
| 入庫・出庫 | 可 | 可 |
| 工具変更履歴の参照 | 可。単価の金額は非表示 | 可 |
| 入出庫履歴 | 本人の入出庫と、その取引に対する管理者の取消 | 全件 |
| 単価の参照・範囲検索 | 不可 | 可 |
| 工具登録時の単価入力 | 可 | 可 |
| 既存工具の単価変更 | 編集画面に欄を出さず、通常の保存では既存値を保持 | 可 |
| 入出庫の取消 | 不可 | 可 |
| ユーザー登録・変更 | 不可 | 可 |

サーバー側で毎回認証・認可します。画面にボタンを隠すだけではなく、APIにも適用します。単価の読み取り制限と、工具登録・変更の権限は別です。

## 3. ログインと共通表示

- `/` は `/login` へ転送し、ログイン成功後は `/dashboard` へ移動します。
- ログインは画面中央の最大448pxのカード内に、社員ID・パスワード・ログインボタンを縦に配置します。
- セッションは無操作30分、ログインから最大8時間で終了します。
- 社員ID単位で15分間に5回までログインを試行でき、6回目以降を制限します。
- 業務画面の最大幅は1600px。ツール名、画面見出し、本人の氏名・社員ID・ロール、ログアウトを表示します。
- メニューはマイページにだけ表示します。その他の認証済み画面には「マイページへ戻る」を表示します。
- 主要操作、補助操作、リンク、展開欄には共通の色・フォーカス表示を使います。背景は薄いグレー、カードは白、主操作は緑系、リンク・補助操作は青系です。
- 表は狭い画面で表の内側を横スクロールします。フォームは画面幅に応じて折り返します。
- エラーは画面に表示します。ユーザー管理では「保存しました。」の成功メッセージと、画面下の権限変更に関する注意文を表示しません。

## 5. 工具検索と一覧

検索欄の順序は「品目コード・品目名・カテゴリー・検索する」です。品目コードと品目名は大文字小文字を区別しない部分一致、カテゴリーは選択した分類との一致で検索します。一覧は品目コード昇順、1ページ50件。検索条件をページ切り替え時も保持します。通常画面の対象は有効な工具です。

表示列は左から以下の順です。工具詳細の「工具情報」も同じ表を使います。

| 列 | 内容 |
| --- | --- |
| 品目コード | 工具詳細へのリンク |
| 品目名 | 工具詳細へのリンク |
| カテゴリー | 日本語の分類名 |
| 在庫 | 工具の保管場所別実在庫の合計 |
| 発注済み | 注文確定済み・一部入荷の発注明細に残る未入荷数の合計 |
| 発注ライン | 工具全体の発注点 |
| 発注数 | 未処理の発注候補数の合計 |
| 単価 | 管理者のみ金額。円記号、桁区切り、小数2桁。未設定・閲覧不可は「—」 |
| 部門 | 部門コード。未設定は「—」 |
| 棚番 | 工具に登録された棚番。未設定は「—」 |

## 6. 工具登録・変更

### 入力項目

| 項目 | 登録 | 変更 | 制限 |
| --- | --- | --- | --- |
| 品目コード | 必須 | 読み取り専用 | 半角英数字・ハイフン・アンダースコア32文字以内。大文字化して一意 |
| 品目名 | 必須 | 必須 | 100文字以内 |
| カテゴリー | 必須選択 | 必須選択 | 下記5種類 |
| 在庫 | 初期値0 | 現在の工具全体の実在庫 | 0～2,147,483,647の整数 |
| 発注済み | 自動集計値0を表示 | 編集欄なし | 発注明細から自動集計 |
| 発注ライン | 初期値0 | 変更可 | 0～2,147,483,647の整数 |
| 発注数 | 初期値0 | 変更可 | 0～2,147,483,647の整数 |
| 単価 | 必須、初期値0.00 | 管理者にのみ表示 | 0以上、整数部12桁・小数部2桁以内 |
| 部門 | 任意選択 | 任意選択 | 下記4コード。未設定可 |
| 棚番 | 任意 | 任意 | 通常100文字以内。既存の長い棚番は保持可能 |
| 状態 | 有効で登録 | 有効・無効を選択 | 工具の物理削除は提供しない |

### カテゴリー・部門

| 表示名 | 保存コード |
| --- | --- |
| ドリル | DRILL |
| エンドミル | END_MILL |
| タップ | TAP |
| リーマ | REAMER |
| チップ | INSERT |

部門は `17314`、`17361`、`17362`、`17363` のみです。候補外の値はサーバーでも拒否します。カテゴリーは既存英語コードと日本語名を読み取り・検索時に対応付けます。登録・更新時は保存コードへ正規化します。

### 保存時の処理

- 工具登録時に工具、在庫方針、内部の在庫参照先、初期在庫、必要な発注候補、監査を同じトランザクションで保存します。
- 正数の初期在庫は入庫履歴も作成します。0では数量0の履歴を作成しません。
- 在庫変更は差分をADJUSTMENTとして記録し、変更前後の残高と操作者を残します。引当数を下回る変更は拒否します。
- 編集画面の表示後に在庫が変わった場合、古い値による上書きを拒否します。
- 発注数の変更では現在のOPEN候補をDISMISSEDにし、正数なら新しいOPEN候補を作成します。同数の保存では作り直しません。
- 発注ラインのみを設定する保存では、内部の安全在庫を0、目標在庫を発注ラインと同値にします。
- メーカー・型番・数量単位は画面に編集欄を出さず、既存値を保持します。新規登録の数量単位は内部既定値「個」です。
- 在庫や取引履歴のある工具は数量単位を変更できません。品目コードも変更できません。
- 「工具全体の在庫方針」の旧入力欄と、旧画面の注意文は表示しません。

### Excel一括登録（2026年11月9日追加）

工具登録画面の「Excelで一括登録する」から利用します。作業者・管理者ともに通常登録と同じ権限です。

1. Excelテンプレートをダウンロード。
2. 品目コード・品目名・カテゴリー・在庫・発注ライン・発注数・単価・部門・棚番を入力。
3. .xlsxをアップロードし、全行の内容・行番号・入力エラーを確認。
4. エラーがない場合だけ「一括登録する」で確定し、マイページへ戻る。

1回200件、ファイル2MB以下。品目コード・品目名・カテゴリー・単価は必須、数量の空欄は0、部門・棚番は未設定可です。分類・部門等の入力制限は通常登録と共通。既存コード・ファイル内重複・列違い・数式・セル結合は拒否します。

確認時は登録しません。確定時にもファイルの内容・権限・重複を再確認し、全件の工具・初期在庫・取引・候補・監査を1トランザクションで保存します。エラー時は全件を戻します。既存工具の更新には使えません。ファイルをサーバーのファイル領域やDBへ保管しません。

## 7. 工具詳細の表示順

1. 工具情報：一覧と共通の表。「工具情報変更」から編集画面へ移動。
2. 工具変更履歴：新しい順に最大3件。
3. 入庫・出庫：常時表示し、sm幅以上では横並び、小さい画面では縦並び。
4. 直近の入出庫履歴：閲覧権限内の最新5件。

保管場所別在庫の旧表、「この工具の履歴」「履歴を検索する」のリンクは表示しません。

### 工具変更履歴

列は「変更日時・変更内容・操作者」。日時は日本時間で秒まで表示し、操作者は氏名と社員IDを表示します。

既存の監査記録から、工具情報、在庫、発注数の変更を読み取ります。変更内容は「棚番：A-01 → B-02」のように表し、同じ値の保存は表示対象にしません。単価を閲覧できない利用者には金額を出さず「単価を変更」と表示します。履歴がなければ「工具の変更履歴はありません。」と表示します。

最大3件は監査イベント単位です。1回の保存で工具情報・在庫・発注数を変えると複数行になることがあります。操作者名は現在のユーザー情報から表示します。削除した過去の記録や、監査のない変更を推測して補いません。

## 8. 入庫・出庫

- 保管場所の選択欄はありません。内部在庫参照先、棚番に一致する在庫、または唯一の有効な在庫を自動で使います。対象を特定できない場合は操作させず案内を表示します。
- 数量は初期値1、正の整数。直接入力と「−」「＋」で変更できます。
- 入庫後・出庫後の見込みを即時表示します。実行時はサーバーで最新在庫を再確認します。
- 通常取引に理由・設備の入力欄はありません。
- 出庫は実在庫から引当を引いた数量を超えられません。入庫後の在庫も整数上限を超えられません。
- 無効な工具・参照先への新規取引は拒否します。
- 在庫・取引履歴・監査を原子的に保存します。二重送信では同一キーと入力を照合し、同じ確定結果を返します。
- 入庫・出庫の成功時は、最新の在庫を反映した対象工具の詳細 `/tools/[id]` へ戻ります。取消の成功時は対象工具で絞り込んだ `/history` へ戻ります。

## 9. 入出庫履歴

### 検索

画面の順序は、品目コード、カテゴリー、入出庫履歴、操作者、開始日、終了日、管理者用の単価下限・上限、検索・条件クリアです。

品目コードは部分一致、カテゴリーは選択式です。入出庫は数量の増減方向で絞ります。操作者は管理者には全ユーザー、作業者には本人だけを候補表示します。本人を選択した場合は本人が操作した取引だけに絞り、他人を指定する要求は拒否します。

日付は日本時間の開始日00:00以上・終了日の翌日00:00未満。単価の上下限は両端を含み、片方のみ指定可能です。作業者の単価検索はAPIでも拒否します。

### 一覧・取消

- 新しい日時、同時刻はIDの降順で1ページ50件。検索条件をページ切り替え時も保持します。
- 列は左から「日時・品目コード・品目名・カテゴリー・入出庫履歴・数量・操作者・在庫数・単価」。
- 入出庫欄は符号で入庫・出庫を表示し、数量は当該取引の絶対値です。
- 在庫数はその在庫参照先における取引直後の実在庫。単価も取引時点の記録を使います。未知の値は「—」。
- 単価変更は過去の取引単価を書き換えません。取消は元の単価を引き継ぎます。
- 管理者だけが一覧内の「取消」を開き、理由を入力して全量を逆取引で取り消せます。
- 元の取引は変更・削除しません。二重取消、取消の再取消、在庫・引当制約を破る取消は拒否します。

## 10. ユーザー管理

管理者のみ利用できます。登録項目は社員ID、氏名、ロール、初期パスワードです。社員IDは半角英大文字・数字・ハイフン・アンダースコア32文字以内、氏名80文字以内、設定するパスワードは12～128文字です。

一覧は社員IDの部分一致検索、1ページ20件。行の「編集」を開いて氏名、ロール、状態、新しいパスワードを変更します。空の新パスワードは変更なしです。操作ボタンは共通スタイルを使います。

ロール・状態・パスワードを変更すると対象セッションを失効します。自分自身の無効化・降格と、有効な管理者がいなくなる変更は禁止します。過去の業務履歴は保持します。

## 11. API

| URL | メソッド | 用途 |
| --- | --- | --- |
| `/api/auth/login` | POST | ログイン |
| `/api/auth/logout` | POST | ログアウト |
| `/api/auth/session` | GET | 現在の利用者 |
| `/api/tools` | GET / POST | 工具検索 / 登録 |
| `/api/tools/[id]` | GET / POST | 工具詳細 / 変更 |
| `/api/tools/[id]/initial-stock` | POST | 管理者用の旧初期在庫登録互換 |
| `/api/tools/import/template` | GET | 認証付きExcelテンプレート |
| `/api/tools/import` | POST | multipartのfileとaction=preview / commitで確認・確定 |
| `/api/inventory/receive` | POST | 入庫 |
| `/api/inventory/issue` | POST | 出庫 |
| `/api/inventory/reverse` | POST | 管理者の取消 |
| `/api/history` | GET | 権限付き履歴検索 |
| `/api/history/[id]` | GET | 履歴1件の互換API。独立した画面はなし |
| `/api/admin/users` | GET / POST | ユーザー一覧 / 登録 |
| `/api/admin/users/[id]` | POST | ユーザー変更 |
| `/api/health/db` | GET | 認証済みのDB接続・toolsテーブル確認 |

通常の書き込みはJSONまたはHTMLフォームを受け、Originを照合します。JSONは結果とHTTPステータス、HTMLフォームは303転送で応答します。通常入力サイズ上限は8KiB。一括登録は専用multipart受付を使い、ファイル2MiB・multipart全体は2MiB+64KiB・展開後8MiBまでに制限します。主なエラーは400（入力）、401（未認証）、403（権限・Origin）、404（未存在）、409（競合）、413（サイズ）、429（ログイン試行制限）、503（接続等）です。

## 12. 今後の機能追加との境界

現在、発注候補数の保存・発注残の読み取り集計はありますが、発注承認、発注書、注文確定、部分入荷、発注明細連携、返品の操作画面・ワークフローは未実装です。

独立した棚卸・保管場所・設備・仕入先・購買条件の管理画面と旧APIは提供しません。過去データや参照整合性を保つため、DBモデルは残っています。工具変更による在庫修正は独立棚卸画面とは別に実装されています。

DBバックアップ・復元の定期実行、本番環境の構築・運用、通知、外部連携は今回の完成範囲外です。今後追加する機能は本書・権限表・DB移行・テストを併せて更新してください。
