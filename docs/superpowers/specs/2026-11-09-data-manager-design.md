# 責任者向けデータ管理

目的: 管理者が全テーブルをシステム内の表で確認・編集する。現在のNext.js / React / Prisma / PostgreSQLを利用し、追加依存・DB移行は不要。

## 対象と構成

- 管理者のみ `/admin/data` と専用APIを利用。マイページのメニューから開き、戻るリンクを設ける。
- 工具、ユーザー、在庫残高、在庫方針、入出庫履歴、発注候補、保管場所、設備、仕入先、仕入条件、発注、発注明細、監査ログ、セッション、ログイン試行の全15種類を選択式で表示。
- 検索・50件ページング。表の入力欄を直接編集。変更行を色で示し、保存前の取消、最大20行の一括保存が可能。一括保存は全件成功または全件取消。
- 主キー・参照先・コード・自動日時・集計値は表示専用。通常の登録画面は引き続き利用できる。
- 在庫変更は差分取引と監査を同時記録。引当数≦実在庫を守る。
- 入出庫履歴の訂正は数量・取引単価と訂正理由を入力し、元の取引を逆取引で取り消して訂正取引を追加する。元の取引、日時、操作者は保存する。取消済み・逆取引は訂正不可。
- 監査ログは閲覧専用。パスワードハッシュ、認証キー等は返却しない。ユーザーのパスワード変更は新しいパスワードの入力のみ。
- セッションはユーザー単位の一覧・一括失効、ログイン試行は既知ユーザーと未登録IDの集約・制限解除。内部ハッシュを表示しない。

## 保存

サーバー側でテーブル・列・型を許可リスト検証。更新日時を比較して上書き競合を409で通知。管理者保護、権限変更時のセッション失効、数量・単価・方針の制約、旧テーブルの参照整合性を維持。全更新に操作者と変更前後を記録し、機密情報は記録しない。

## 検討した方式

通常画面の表をすべて編集可能にする方式は、作業者の普段の操作と責任者の保守操作が混在する。管理者専用画面を追加し、全テーブルに共通の表と個別の業務検証を組み合わせる。ユーザーが選択した「システム内の表形式編集」「全て」を対象とする。

## 検証

権限・秘密情報の非公開、全テーブルの一覧、入力検証、複数行ロールバック、同時編集、管理者の保護、在庫と履歴の整合、訂正の二重実行、画面・APIの経路をテストする。
