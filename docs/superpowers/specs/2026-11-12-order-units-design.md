# 発注単位・在庫単位の分離と入出庫金額

## 合意済みの目的

2026-11-12の会話で、発注単位あたりの仕入単価、工具別の入数、在庫単位への換算、出庫時のマスター単価による使用金額、過去の価格固定を採用した。利用者は「それで進めてみよう」と実装を指示した。本書はその合意を記録し、追加の実装判断を明記する。

10個入り5,000円のチップは、2箱発注で発注済み20個、1箱入庫で在庫10個増・発注残10個、3個出庫で単価500円・金額1,500円となる。入数3も扱う。入数1の工具は従来どおり。

## 比較した方法

- 発注数量を手作業で個数に直す方法は、入力の乖離を防げない。
- 発注単位・在庫単位・入数を分離する方法を採用。数量を比較するときは在庫単位に統一する。
- 仕入実績による移動平均単価は採用しない。利用者が定期的にマスター価格を一括変更し、出庫時のマスター価格を使用する方針を選択した。

## 現状と変更範囲

- Tool.unitを在庫単位、Tool.unit_priceを発注単位あたりの仕入単価として使う。order_unitとunits_per_orderを追加する。
- 現行の発注リストは参照専用で「発注」欄は空。外部で発注した事実を登録する機能と、入庫による発注残消込が必要。
- 旧PurchaseOrderは仕入先などを必須とし、現行画面から作成できない。仕入先を新設する運用は導入せず、工具別の軽量な発注記録ToolOrderを追加する（実装側の提案）。旧注文が存在する場合は発注残集計を維持する。
- docs/superpowers/specs/2026-11-11-remove-purchasing-design.mdには旧発注構造の削除案があるが、現行コード・DB定義では削除されていない。今回の範囲にその削除や旧注文の移行を含めない。
- Excel出力・一括変更の未コミット変更を保持し、その上に単位項目を追加する。他作業のコミット・巻き戻しを行わない。

## 数量と操作

1. 工具登録・変更に在庫単位、発注単位、入数を表示する。入数は1～2,147,483,647の整数。既存工具は発注単位を在庫単位と同じ、入数1で初期化する。既存価格・在庫の数値は変更しない。
2. 発注数（既存OPEN候補）は発注単位の数量として扱う。既存値は変更しない。発注ラインは在庫単位。
3. 管理者が発注リストで発注数量を指定し「発注済みに登録」する。操作は外部業者に送信せず、ToolOrderに記録する。発注時点の発注単位・入数・仕入単価と、在庫換算数量を固定保存する。OPEN候補数量は定期発注の設定値として維持し、発注リストの該当行だけを消す。
4. 工具詳細に未入庫の発注記録を表示し、対象発注を選んで入庫する。発注単位で受ける場合は発注時の入数で換算する。在庫単位での一部入庫も可能。紐付けない通常入庫は発注残を減らさない。
5. 入庫、在庫追加、発注残消込、履歴、監査は一つのトランザクション。取消では元の入庫に紐付く発注残も戻す。過剰入庫は拒否する。未入庫残のみ管理者が発注取消でき、受領済み部分は保持する。
6. 発注済みは未入庫の在庫換算数量の合計。既存旧注文の数量は従来の在庫単位として加算し、現行マスターの入数を掛けない。新旧記録の二重消込はしない。
7. 現行の発注リスト判定（在庫 < 発注ライン + 発注残）は今回変更しない。発注残の換算だけを正しくする。発注時に消した行は、その後の条件該当出庫で再登録され得る。
8. マスター変更・価格一括変更・発注・入庫は工具行を同じ順序でロックする。二重送信と再試行はrequest_keyにより同じ結果を返し、異なる内容へのキー流用は409とする。

## 金額と履歴

- 在庫単価 = 処理時点のマスター仕入単価 / 処理時点の入数。入庫が発注記録に紐付いても、金額は処理時点のマスター基準とする。数量換算の入数は発注時の値を使う。
- 各履歴に単価、仕入単価と入数の計算根拠、在庫単位、符号付き取引金額を保存する。在庫単価はDecimal(24,8)、取引金額はDecimal(24,2)。最大価格×最大数量も保存可能とする。
- 取引金額 = マスター仕入単価 × 符号付き在庫数量 / マスター入数を直接計算し、小数第3位を四捨五入する。丸め済み単価を掛けない。JSの浮動小数点では金額を計算しない。
- 例：1,000円/3個を3個出庫した金額は1,000.00円。1個出庫は333.33円。個別取引を丸めた合計と箱の価格との差は、標準使用金額として許容する。
- 取消は元の単価と計算根拠をコピーし、元の取引金額の符号を反転する。取消時のマスターは参照しない。
- 初期在庫、登録時の初期入庫、在庫手修正にも共通の計算を使う。単価未設定は単価・金額ともnull、0円とは区別する。
- 既存履歴の単価は変更しない。金額を補完する場合は保存済み単価×数量のみ使用し、cost_basis='LEGACY'とする。新履歴は'MASTER'。当時の入数を推測した再計算はしない。価格のない履歴は金額もnull。
- 履歴の「単価」を在庫単位あたりの値と明記し、「金額」を追加する。通常の取引金額は絶対値表示、取消は取消種別と戻し金額を識別できる表示とする。小数は最大2桁まで表示し、333.33円を333円だけに隠さない。
- 将来の月別使用金額は、ISSUEの取引金額の符号を反転した値と、ISSUEを打ち消すREVERSALを合計する。初期入庫・通常入庫・在庫調整は使用金額に含めない。集計日はAsia/Tokyoの取引日、取消は取消を実行した月に計上する（実装側の提案）。月別グラフ・集計画面は後続作業。

## Excelと互換性

- 現行9列の末尾に「在庫単位」「発注単位」「入数」を追加する。既存「単価」列は発注単位あたりの仕入単価と説明する。出力→一括変更の往復で項目を保持する。
- 旧9列も読み込める。旧形式の新規登録は在庫単位=個、発注単位=個、入数=1。一括変更で追加列がなければ現在値を保持する。
- 新形式の空欄は登録時に在庫単位=個、発注単位=在庫単位、入数=1。更新時の空欄は保持。履歴・在庫のある工具の在庫単位変更は従来同様拒否。
- 入数変更と価格一括変更はプレビュー前後の値を表示し、確定までにマスターが変更されていれば409にする。
- 入数・価格を変更しても、過去の発注・入出庫・発注残の個数は変わらない。

## 移行と検証

追加マイグレーションで行い、既存移行は書き換えない。専用テストDBで移行前後の数量と価格を検証する。通常利用DBへの移行は既存手順でバックアップした後に行い、コードの検証結果と実DBの適用状況を分けて報告する。

10個/箱と3個/箱、入数1、未知価格・0円・最大値、価格変更後の取消、旧履歴、旧Excel、同時更新・二重送信、部分入庫と取消、権限のサービス/APIテストを実行する。型検査、既存の関係テスト、本番ビルドを実行し、画面の登録→発注→一部入庫→出庫→取消の一連の操作を確認する。
