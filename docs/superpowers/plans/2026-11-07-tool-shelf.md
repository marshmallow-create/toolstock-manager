# 工具に棚番を保持する

ユーザーの指示: 管理者の保管場所管理を廃止し、棚番は工具の情報にする。

- [x] 工具ごとの棚番保存・編集と旧棚マスタからの独立をテストする。
- [x] tools.shelf_codeを追加し、既存の棚番を在庫行から移行する。複数の棚はコード順で併記し、在庫・履歴は変更しない。
- [x] 登録・編集・一覧・詳細で工具の棚番を使用する。新しい工具の初期在庫は棚番と独立した内部の在庫行に記録する。
- [x] 保管場所管理画面・メニュー・管理APIを廃止する。既存の在庫・履歴の参照先は保持する。
- [x] 全テスト・本番ビルド・移行と実画面を検証する。

既存の場所別在庫や履歴の構造は互換性のため維持する。工具の棚番を変更しても在庫の移動や過去の取引の書き換えは行わない。入出庫に使う内部在庫行は別管理画面を必要としない。旧サービスの保管場所ヘルパーは既存の内部処理・テストで引き続き使うが、利用者向け管理APIは公開しない。

検証: 全79テストと本番ビルドが成功。移行SQLのテストで複数棚番の保持、在庫行・履歴行の完全一致を確認。独立レビューの2指摘（内部在庫候補の混在、移行済み棚番の長さ制限）を修正し再レビュー済み。ローカルDBへ移行適用。開発サーバー再起動後、一覧APIのshelf_code、編集欄、メニュー削除、旧管理画面404を確認。
