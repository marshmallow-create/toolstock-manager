# Excel工具一括登録・変更

管理者が `/tools/import` で「新規登録」と「既存工具の変更」を切り替え、対応するテンプレートを取得して内容確認・一括確定を行います。通常の1件登録は両ロールに許可し、一括登録・変更は `tools:import` 権限で管理者に制限します。

## 入力と確認

- `.xlsx` のみ、2MiB以下、空行を除いて200件まで。
- 列は品目コード・品目名・カテゴリー・在庫・発注ライン・発注数・単価・部門・棚番・在庫単位・発注単位・入数の12列。旧9列のファイルも受け付けます。テンプレートに日本語見出しと候補・説明を含めます。
- 新規登録は「工具登録」シートを使います。品目コード・品目名・カテゴリー・単価は必須。数量の空欄は0、部門・棚番は未設定可で、既存コードは登録できません。
- 変更は「工具変更」シートを使います。既存工具と一致する品目コードが必須で、他の項目は変更する値だけを入力します。空欄は現在値を保持し、0は0への変更として扱います。部門・棚番も空欄で消去できません。カテゴリーは空欄可です。未登録コードは変更できません。
- 値の制限は[通常登録・変更](specification.md)と共通です。ファイル内の正規化後重複、数式、結合、想定外の列構成を拒否します。別モードのシートも受け付けません。
- 単価列は `numFmt: '0'` とし、1円単位に四捨五入した金額を表示します。小数部2桁以内の入力は受け付け、入力した小数値を保持して取り込みます。DBの `Decimal(14,2)` を変更せず、工具の仕入価格表示は小数なし、入出庫履歴は単価・金額の小数を最大2桁まで表示します。
- 確認画面に全件・行番号・エラーを表示し、変更は各項目の変更前→変更後を確認できます。確認時はDBに書き込まず、全件正常な場合のみ確定できます。

## 工具一覧のダウンロード

管理者はマイページの工具一覧にある「Excelダウンロード」から、現在の検索条件に一致する有効な工具を全ページ分、品目コード順で取得できます。作業者にはボタンと出力の説明を表示せず、APIへの直接アクセスも403で拒否します。一括変更の確認・確定も管理者のみが利用できます。

出力は変更テンプレートと同じ「工具変更」シート・12列です。現在庫、発注ライン、未処理の発注数、仕入単価、部門、棚番、在庫単位、発注単位、入数の現在値が入ります。品目コードなどの先頭0と単価の小数部を保持し、単価の表示は既存テンプレートと同じ整数表示です。該当なしの場合は、その旨を「入力方法」に記載した空の変更テンプレートを返します。

200件以下は `toolstock-update.xlsx`、200件超は200件ずつのExcelを含む `toolstock-update.zip` をダウンロードします。ZIPは展開し、各Excelを個別に一括変更へアップロードしてください。品目コードは変更せず、変更対象以外の行は削除します。出力後に在庫などが変わる場合があるため、変更しない項目は空欄にし、確認画面の変更前後を確認してから確定してください。

`GET /api/tools/export` は `tool_code`・`name`・`category`・互換検索語の `q` を受け付けます。`page` は出力件数を制限しません。APIでも管理者専用の `tools:export` 権限で認証・認可を行い、レスポンスは `Cache-Control: no-store` としてファイルをサーバーへ保存しません。

## 取り込みAPIとモード

`GET /api/tools/import/template` は登録用、`?mode=update` は変更用テンプレート `toolstock-update.xlsx` を返します。`POST /api/tools/import` はmultipartの `file`、`action`（`preview` / `commit`）、`mode`（`create` / `update`）を受け取ります。mode省略時は従来と同じcreateです。

変更の確認結果に `previewToken` を含めます。変更確定のmultipartには、確認したファイル・mode・action=commitとともにこのトークンを送信します。新規登録の互換APIではトークンを必要としません。

## 保存と保護

ページ・テンプレート・確認・確定APIと保存トランザクションで認可します。確認後に権限やDBの内容が変わった場合にも、確定時の再解析・認可・重複検証を適用します。

変更の `previewToken` は、ファイルから解析した行と、現在の工具・全在庫・在庫方針・OPEN発注候補の指紋に対応します。確定トランザクションで再取得した状態と照合し、確認後に対象データやファイルが変わった場合、またはトークンがない場合は409で拒否します。最新の内容を再確認してから確定します。

新規登録は工具、内部在庫参照先、初期在庫、必要な取引・発注候補・監査を全件1トランザクションで保存します。変更も全件1トランザクションとし、通常変更と共通の処理で在庫差分のADJUSTMENT、発注候補の更新、監査・工具変更履歴を残します。途中失敗は全件ロールバックし、新規登録の再送は品目コードの一意制約で二重登録を防ぎます。ファイルは確認中にブラウザが保持し、サーバーのファイル領域やDBへ保存しません。

通常の8KiB入力制限とは別にmultipartを受け付け、全体を2MiB+64KiB、展開後を8MiBに制限します。ZIPエントリー数、XMLの行・セル・シートIDも検査します。名前付き範囲、外部参照、マクロ、DOCTYPE、非標準のZIPパス等を拒否し、任意のExcelブック全般は取り込みません。

## 単位と入数の互換性

末尾のJ列が在庫単位、K列が発注単位、L列が入数です。単位は16文字以内、入数は1～2,147,483,647の整数。単価は発注単位あたりの仕入価格で、在庫と発注ラインは在庫単位、発注数は発注単位です。

新規登録の単位空欄は在庫単位「個」、発注単位は在庫単位と同じ、入数1です。旧9列からの新規登録も個・個・1です。一括変更の省略列・空欄は現在値を保持するため、旧9列の価格更新でも箱・入数は変わりません。既存在庫・履歴がある工具の在庫単位変更は拒否します。入数や単価が確認後に変われば再確認を求めます。保存済み発注と過去履歴の換算値は変更しません。
