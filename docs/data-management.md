# 責任者向けデータ管理

管理者でログインし、マイページの「メニュー」→「データ管理」を開きます。作業者にはメニューを表示せず、画面・APIも利用できません。

## 表での編集

1. 「対象データ」で編集したいテーブルを選択します。検索欄にはコード・名称などを入力できます。
2. 表の入力欄を変更します。変更した行には「変更あり」と表示し、背景色も変わります。
3. 「変更をまとめて保存」で、最大20行を同時保存します。すべて成功するか、すべて元に戻ります。
4. 「変更を元に戻す」は未保存の変更を取り消します。行単位でも戻せます。

一覧は50件ずつ表示します。未保存の変更があるときは検索・対象切替・ページ移動の前に確認します。保存エラーでは入力を残し、再試行できます。別の操作で更新された行は競合エラーにし、古い画面の内容で上書きしません。

## 対象

| 区分 | 対象 | 操作 |
| --- | --- | --- |
| 工具・在庫 | 工具、在庫残高、在庫方針 | セル編集 |
| ユーザー | ユーザー | 氏名・ロール・状態・新しいパスワード |
| 履歴 | 入出庫履歴 | 増減数量・取引単価の訂正。訂正理由必須 |
| 履歴 | 監査ログ | 閲覧のみ |
| 発注 | 発注候補、発注、発注明細 | 数量・状態・条件の編集 |
| 参照マスタ | 保管場所、設備、仕入先、仕入条件 | 名称・状態・条件の編集 |
| 認証 | ログインセッション | ユーザー単位の全セッション失効 |
| 認証 | ログイン試行 | 失敗回数の確認・制限解除 |

新しい工具・ユーザーの登録は既存の登録画面を使います。主キー・コード・参照先・作成日時・操作者は表から書き換えません。物理削除は提供しません。

## 在庫と履歴

実在庫を変更すると、増減分を在庫調整の履歴として記録します。引当数が実在庫を超える変更は保存できません。在庫方針は安全在庫≦発注点≦目標在庫、発注明細は入荷済数量≦発注数量を守ります。

履歴の訂正では元の取引を変更せず、逆取引と訂正取引を同時に追加します。数量は増減を表す符号付きで、入庫は正、出庫は負です。元の日時・操作者・確定値は残り、訂正した管理者と理由を記録します。取消済みの履歴や逆取引は訂正できません。取り消すと在庫不足になる取引は訂正を拒否します。

監査ログを編集・削除する機能は設けていません。パスワードハッシュ・認証キー・ログイン試行キーは返却しません。監査ログ内でも機密項目は除外します。ユーザーの権限・状態・パスワードを変更すると、そのユーザーのセッションを失効します。自分自身の無効化・降格はできません。

旧テーブルの表示・編集はデータ保守のための機能です。廃止した通常画面・APIや、未実装の発注承認ワークフローを再開するものではありません。

## 検証

`npm run test:data-manager` は権限、入力、原子的保存、競合、在庫・履歴訂正、認証管理を検証します。`npm run build` 後の `npm run test:data-manager-http` は管理者画面・API・メニュー・検索・保存を検証します。`npm test` にも含まれます。
