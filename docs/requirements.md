# 要件（Phase 1）

基準: ../Markdown/ToolStock_Manager_Codex_開発指示.md v1.0。

対象は1工場の切削工具。手動出庫と棚別在庫、操作者別履歴、発注点による候補と購買承認を最終目標とする。

今回: Next.js App Router / TypeScript / Tailwind、PostgreSQL Compose、Prismaモデル・初期DDL・架空シード、トップ画面とDB接続確認、開発・テスト・停止手順。

対象外: 認証実装、マスタ編集、入出庫API、発注判定/承認/送信、本番デプロイ。これらの画面は実装しない。

受入条件: ローカルDB起動、マイグレーション、シード、Web起動が正常完了すること。2026-11-03にDB接続、初期DDL適用、シード投入・再実行不変、DBテスト、型検査、ビルド、WebトップとDB接続APIのHTTP 200を確認し、Phase 1の主要受入条件を達成。

不変条件: 整数数量、非負在庫、引当超過禁止、ユニーク業務コード、参照先削除禁止、履歴追記型、UTC保存。アプリの認可と競合制御は後続実装時にも必須。


## Phase 2

利用者の開始指示に基づき、社員IDログイン・DBセッション・4ロールの認可・ユーザー登録/変更/無効化を実装。共有端末のログアウトと期限、既存セッションの無効化反映、試行制限、Origin照合を含む。15件のテストと型検査/ビルドにより、現在提供する画面・APIの制限を確認。工具/在庫マスタ編集はPhase 3以降。

## Phase 3 — 工具・在庫マスタ

利用者が設計案を承認し、工具検索・マスタ管理・購買条件・棚別在庫・初期在庫登録を実装した。詳細は docs/superpowers/specs/2026-11-03-phase3-masters-design.md と同 plans/2026-11-03-phase3-masters.md。

全ロールが工具番号・名称・型番で検索し、分類・有効状態で絞り込める。工具一覧は50件単位。工具詳細は棚別の実在庫・引当・出庫可能数と在庫方針を表示する。在庫管理者・管理者が工具・設備・保管場所・仕入先・購買条件を登録・更新・無効化でき、購買担当は購買条件を閲覧できる。作業者には仕入先条件・単価を公開しない。

初期在庫は未登録の工具×保管場所へ一度だけ登録できる。0も登録済みとして扱い、正数は入庫履歴と、0/正数ともに監査を同一トランザクションで保存する。同じキー・内容・操作者の再送では再計上せず、異内容や別キーでの再登録は拒否する。

手動出庫・通常入庫・棚卸訂正・履歴検索はPhase 4、発注候補・承認・出力はPhase 5。今回は追加しない。
