# 要件（Phase 1）

基準: ../Markdown/ToolStock_Manager_Codex_開発指示.md v1.0。

対象は1工場の切削工具。手動出庫と棚別在庫、操作者別履歴、発注点による候補と購買承認を最終目標とする。

今回: Next.js App Router / TypeScript / Tailwind、PostgreSQL Compose、Prismaモデル・初期DDL・架空シード、トップ画面とDB接続確認、開発・テスト・停止手順。

対象外: 認証実装、マスタ編集、入出庫API、発注判定/承認/送信、本番デプロイ。これらの画面は実装しない。

受入条件: ローカルDB起動、マイグレーション、シード、Web起動が正常完了すること。2026-11-03にDB接続、初期DDL適用、シード投入・再実行不変、DBテスト、型検査、ビルド、WebトップとDB接続APIのHTTP 200を確認し、Phase 1の主要受入条件を達成。

不変条件: 整数数量、非負在庫、引当超過禁止、ユニーク業務コード、参照先削除禁止、履歴追記型、UTC保存。アプリの認可と競合制御は後続実装時にも必須。


## Phase 2

利用者の開始指示に基づき、社員IDログイン・DBセッション・ロールの認可・ユーザー登録/変更/無効化を実装。現在のロールは作業者（WORKER）と管理者（ADMIN）の2種類。共有端末のログアウトと期限、既存セッションの無効化反映、試行制限、Origin照合を含む。Phase 2当時は15件のテストと型検査/ビルドにより画面・APIの制限を確認。工具/在庫マスタ編集はPhase 3以降。

## Phase 3 — 工具・在庫マスタ

利用者が設計案を承認し、工具検索・マスタ管理・購買条件・棚別在庫・初期在庫登録を実装した。詳細は docs/superpowers/specs/2026-11-03-phase3-masters-design.md と同 plans/2026-11-03-phase3-masters.md。

両ロールが工具番号・名称・型番で検索し、分類・有効状態で絞り込める。工具一覧は50件単位。工具詳細は棚別の実在庫・引当・出庫可能数と在庫方針を表示する。管理者が工具・設備・保管場所・仕入先・購買条件を登録・更新・無効化できる。単価・仕入先条件の閲覧・編集は管理者だけに許可し、作業者には公開しない。

初期在庫は未登録の工具×保管場所へ一度だけ登録できる。0も登録済みとして扱い、正数は入庫履歴と、0/正数ともに監査を同一トランザクションで保存する。同じキー・内容・操作者の再送では再計上せず、異内容や別キーでの再登録は拒否する。

手動出庫・通常入庫・棚卸訂正・履歴検索はPhase 4、発注候補・承認・出力はPhase 5。今回は追加しない。

## Phase 4 — 手動入出庫・棚卸訂正・履歴

利用者が設計案と実装・テストを承認。出庫、理由付き手動入庫、実棚数の反映、全量逆取引、期間・工具・設備・操作者・種別での履歴検索を追加した。詳細は superpowers/specs/2026-11-04-phase4-inventory-design.md。

出庫は設備必須で、実在庫から引当を除いた数量まで。入庫は未登録棚にも登録できる。棚卸は確認時の実在庫・引当が現在値と一致する場合だけ差分を保存する。訂正は理由付きの逆取引で元履歴を保持し、正しい内容は新規取引として登録する。同じUUIDの再送では在庫を二重計上しない。

作業者は本人の出庫と、その出庫を管理者が取り消した逆取引だけを閲覧できる。管理者は全履歴を参照できる。手動入庫・棚卸・逆取引は管理者のみ。工具詳細の直近履歴にも同じ閲覧制約を適用する。

発注候補・承認・注文書・発注残にひも付く部分入荷・返品はPhase 5以降。Phase 4では発注書からの入庫入力を受け付けない。
