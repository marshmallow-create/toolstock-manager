# 保守

起動手順は[README](../README.md)、現行の基準は[仕様](specification.md)、移行の内容は[DB](database.md)です。

## 開発と保存

- 既存の未コミット変更を維持し、依頼範囲を作業します。設定と依存の正本はプロジェクトルートです。
- 認証・権限・Origin照合をサーバー側で行い、在庫・発注・監査を同一トランザクションで保存します。
- 数量は整数、価格はDecimal、保存日時はUTC、表示は日本時間です。
- 入出庫履歴・監査は追記型です。成功済み要求の再送互換を維持します。
- DB構造は追加移行で変更し、既存移行・CHECK・外部キー・履歴保護を保持します。
- 資格情報、.env、バックアップ、ローカル生成物をGitに含めません。

全体テストは専用TEST_DATABASE_URLの一時スキーマを作成し、終了時に削除します。テスト対象は権限、認証・本人パスワード変更、各移行、工具、在庫・履歴・取消、発注確認と入庫消込、Excel、HTTP、本番ビルドです。移行テストの旧構造は互換性を検証するため残します。

過去のテスト件数・ブラウザ画像を現在の検証結果として流用しません。必要な検証を実行し、失敗や未実施を記録します。実機タブレット・スクリーンリーダー・本番運用・実復元の確認は、各環境で別途実施します。

## バックアップと復元

削除を伴うDB更新の前に `npm.cmd run db:backup` を実行します。バックアップ処理はローカルtoolstock_devとComposeの接続先一致を確認し、全体ダンプとJSONメタデータをbackupsへ保存します。pg_restore --list、ファイル形式、SHA-256を確認します。

復元はアプリを停止し、バックアップ時点と同じスキーマ・コードを使用します。まず別の検証DBへ復元し、工具・在庫・発注残・取引・監査を照合します。現在のDBへ無条件で上書きしません。

```powershell
docker compose exec db createdb -U toolstock toolstock_restore_test
docker compose cp backups/toolstock.dump db:/tmp/restore.dump
docker compose exec db pg_restore -U toolstock -d toolstock_restore_test --no-owner --exit-on-error /tmp/restore.dump
```

このコマンドは手順例です。今回の整理では実復元を行いません。適用済み移行の再実行、DBボリューム削除、業務データの再シードは通常手順に含みません。
