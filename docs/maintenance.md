# 保守

起動・検証の入口は[README](../README.md)、機能と権限の基準は[現行仕様書](specification.md)です。

## 開発ルール

- 作業前に既存ファイルとGit状態を確認し、未コミットの変更を上書きしません。npm・TypeScript設定の正本はプロジェクトルートです。
- 利用者が依頼した範囲を実装します。発注ワークフロー、本番運用、外部連携の追加は別途指示に従います。実データ・本番DB・外部デプロイ・実メール送信・実発注は扱いません。
- `.env`、資格情報、`.local/`、バックアップをコミットしません。`.local/dev-credentials.json` の値をログ・文書・報告へ転記しません。シードは架空情報だけを扱います。
- 認証・認可は `src/lib/auth/`、入出庫は `src/lib/inventory/` を共用します。書き込みにはサーバー側の認可とOrigin照合を適用します。
- 数量は整数、金額はDecimal、保存日時はUTC、画面表示はAsia/Tokyoを維持します。
- 在庫整合性、追記型の取引・監査、成功済み要求の再送互換を保ちます。DB変更は追加移行で行い、SQLのCHECK・部分一意索引・履歴保護トリガーを維持します。
- 仕様判断は該当する現行文書へ反映し、変更内容・検証結果・残課題を日本語で報告します。未実行の確認を成功と報告しません。

## 整理方針

READMEと本ディレクトリの仕様・構成・DB・Excel・保守を現行資料とします。旧開発指示、重複README、参照だけの要件書、完了済みの設計判断の時系列記録は削除し、継続して必要な仕様・制約・作業ルールを現行資料へ集約します。旧DB整理の退避・単価移行・再送・復元の注意点は[DB設計](database.md)へ統合します。

ソース、テスト、適用済み移行、ロックファイル、運用スクリプトは現在の実装と検証に必要なものを残します。`.env`、`.local/`、DBボリューム、バックアップは実行環境のデータとして保持します。`.local/development-snapshots/` の古いJSONは一部項目の記録で、完全なDBバックアップではありません。

`.cache/`、`.next/`、依存のキャッシュは再生成できますが、稼働中のサーバー・検証が使用中のファイルを削除しません。

今回の整理では、呼び出し元のない旧マスタ編集サービス、未使用の権限・表示定義、単価参照だけの中継関数を削除しました。テスト用の棚はテスト内で直接作成し、廃止した業務機能へ依存しません。型チェックの対象はソース・テスト・運用スクリプト・Prisma設定に限定します。

完了した調査・確認スクリプト、スクリーンショット、Excel検証ファイル、ブラウザプロファイル、テスト出力、npmキャッシュ、停止中の開発サーバーのキャッシュを除去しました。開発サーバーの実行ログと本番ビルドは保持します。
